## Local Setup

Install Node dependencies from repo root:

```bash
npm install
```

Use the full Homebrew ffmpeg, because the default `/opt/homebrew/bin/ffmpeg` on this machine did not include `drawtext`:

```bash
brew install ffmpeg-full
export PATH="/opt/homebrew/opt/ffmpeg-full/bin:$PATH"
```

Set up stitchlab Python dependencies:

```bash
python3 -m venv pipeline/stitch/.venv
pipeline/stitch/.venv/bin/python -m pip install --upgrade pip wheel setuptools
pipeline/stitch/.venv/bin/python -m pip install opencv-python-headless numpy
```

Playwright wrapper was made executable on this machine and linked as:

```bash

```

## Import Command

The legacy MMM importer maps the nine MMM proxy files into the normal Plate Lab drop shape without recreating MMM's camera proxies:

```bash
PATH="/opt/homebrew/opt/ffmpeg-full/bin:$PATH" \
npx -w pipeline tsx src/demo/import-legacy-mmm.ts \
  /Volumes/SMB/01042024_GA_DTLA/MMM_LEGACY_SORT/SPH-STK-LEGACY-20260803-GA-DTLA-DTLA-DAY01 \
  CLIP-0010 \
  legacy-ga-dtla-clip-0010
```

Camera mapping is `CAM_01..CAM_08 -> A..H` and `CAM_09 -> J`.

The importer preserves the raw legacy GPS/IMU file as `gps_imu.source.json` and converts the full GPS sequence into `telemetry.json`. For `CLIP-0010`, the local source had 1,917 GPS samples and 1,917 IMU samples.

## Stitch Work So Far

The first generated preview was wrong because the standard ingest fallback only makes a six-camera ring strip. I replaced the local `PL-7014298` preview with a calibrated ring render from stitchlab:

```bash
PATH="/opt/homebrew/opt/ffmpeg-full/bin:$PATH" \
PYTHONPATH=pipeline/stitch \
pipeline/stitch/.venv/bin/python -m stitchlab stitch \
  --drop sample-data/drops/legacy-ga-dtla-clip-0010 \
  --pts /Users/spherislivestitch/Projects/codie_livestitch/config/calibration.pts \
  --out sample-data/stitch-runs/legacy-ga-dtla-clip-0010-ring-full \
  --full
```

Then promoted the full-coverage ring band:

```bash
PATH="/opt/homebrew/opt/ffmpeg-full/bin:$PATH" \
PYTHONPATH=pipeline/stitch \
pipeline/stitch/.venv/bin/python -m stitchlab promote \
  --run sample-data/stitch-runs/legacy-ga-dtla-clip-0010-ring-full \
  --pts /Users/spherislivestitch/Projects/codie_livestitch/config/calibration.pts \
  --sku PL-7014298 \
  --label "GA DTLA - Day Urban" \
  --width 3072
```

The promoted local site preview was `3072x414`, 24 fps, 80.791667 seconds, 1,939 frames.

## Open Issue

The calibrated ring preview is still not production quality. A bad seam is visible around the F-A-B region near the viaduct, especially around `24:13` as called out in review.

Measured ring-stitch sample metrics showed F-A and A-B as outliers:

- F-A: mean absolute linear diff about `0.0343`, phase displacement about `(18.3, -17.3)` px
- A-B: mean absolute linear diff about `0.0519`, phase displacement about `(18.8, 22.3)` px

Temporal activity analysis suggested large whole-frame offsets on the ring cameras, but a temporal-corrected `stitch9` sample did not visually fix the F-A/A-B structure doubling by itself. A focused structure-first round with `ring-routing=ON` improved ring ghost energy (`0.13267 -> 0.04371`) but still had over-bar structure records, so do not ship that output without further QC.

Generated stitch/QC artifacts are intentionally ignored via `sample-data/stitch-runs/`.
